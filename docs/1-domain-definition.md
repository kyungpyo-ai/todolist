## 1. 프로젝트 개요

### 문제 정의

- 인증된 사용자 개인별로 할일을 관리할 수 있는 도구가 없다.
- 할일 관리 시 시작일과 종료일을 지정하고 추적할 수 있는 기능이 부재하다.

### 목표

인증 기반의 개인 할일 관리 애플리케이션을 제공하여, 사용자가 카테고리와 날짜 범위를 기반으로 할일을 효율적으로 등록, 조회, 관리할 수 있도록 한다.

## 2. 핵심 도메인 개념

### User (사용자)

| 속성 | 타입 | 설명 |
|------|------|------|
| id | UUID | 사용자 고유 식별자 |
| email | String | 로그인 이메일 (고유, 형식 검증 필요) |
| password | String | 암호화된 비밀번호 (최소 8자, 영문+숫자 조합) |
| name | String | 사용자 이름 |
| theme | Enum | UI 테마 (`light` \| `dark`, 기본값: `light`) **[v2]** |
| language | Enum | UI 언어 (`ko` \| `en`, 기본값: `ko`) **[v2]** |
| createdAt | DateTime | 가입일시 |
| updatedAt | DateTime | 정보 수정일시 |

### Category (카테고리)

| 속성 | 타입 | 설명 |
|------|------|------|
| id | UUID | 카테고리 고유 식별자 |
| name | String | 카테고리 이름 |
| userId | UUID | 소유 사용자 ID |
| isDefault | Boolean | 기본 카테고리 여부 |
| createdAt | DateTime | 생성일시 |
| updatedAt | DateTime | 수정일시 |

**기본 카테고리 정책:**
- 회원가입 완료 시 서버가 자동으로 `기본` 카테고리를 생성한다.
- `기본` 카테고리는 수정·삭제할 수 없다.
- 사용자가 직접 생성한 카테고리는 수정·삭제 가능하다.

### Todo (할일)

| 속성 | 타입 | 설명 |
|------|------|------|
| id | UUID | 할일 고유 식별자 |
| userId | UUID | 소유 사용자 ID |
| categoryId | UUID | 카테고리 ID (미지정 시 기본 카테고리) |
| title | String | 할일 제목 (최대 200자) |
| description | String | 상세 내용 (선택, 최대 1000자) |
| startDate | Date | 시작일자 (YYYY-MM-DD) |
| endDate | Date | 종료일자 (YYYY-MM-DD) |
| status | Enum | 상태 (NOT_STARTED / IN_PROGRESS / DONE) |
| createdAt | DateTime | 등록일시 |
| updatedAt | DateTime | 수정일시 |

## 3. 도메인 규칙

| ID | 규칙명 | 내용 |
|----|--------|------|
| BR-01 | 인증 필수 | 모든 기능은 로그인한 사용자만 이용할 수 있다. |
| BR-02 | 데이터 격리 | 사용자는 자신의 할일과 카테고리만 조회·수정·삭제할 수 있다. |
| BR-03 | 기본 카테고리 자동 적용 | 할일 등록 시 카테고리를 지정하지 않으면 자동으로 `기본` 카테고리가 적용된다. |
| BR-04 | 날짜 유효성 | 종료일자는 시작일자와 같거나 이후여야 한다. (`endDate >= startDate`) |
| BR-05 | 상태 전이 제한 | Todo 상태는 섹션 5에 정의된 허용 전이 경로로만 변경된다. |
| BR-06 | 본인 정보 수정 | 사용자는 자신의 이름·비밀번호만 수정할 수 있다. |
| BR-07 | 기본 카테고리 보호 | `기본` 카테고리는 수정·삭제할 수 없다. |
| BR-08 | 회원 탈퇴 시 데이터 처리 | 회원 탈퇴 시 해당 사용자의 모든 Todo와 카테고리를 삭제한다. |
| BR-09 | 이메일 중복 금지 | 이미 가입된 이메일로는 회원가입할 수 없다. |
| BR-10 | 테마 설정 저장 [v2] | 사용자가 선택한 테마(`light`/`dark`)는 서버 DB에 저장되며, 로그인 시 저장된 테마가 자동 적용된다. |
| BR-11 | 언어 설정 저장 [v2] | 사용자가 선택한 언어(`ko`/`en`)는 서버 DB에 저장되며, 로그인 시 저장된 언어가 자동 적용된다. |

## 5. Todo 상태 정의

### 상태 목록

| 상태 | 코드 | 설명 |
|------|------|------|
| 시작 전 | `NOT_STARTED` | 할일이 등록되었으나 아직 시작하지 않은 상태 |
| 진행 중 | `IN_PROGRESS` | 할일을 진행 중인 상태 |
| 완료 | `DONE` | 할일이 완료된 상태 |

### 상태 전이 (허용 경로)

```
NOT_STARTED → IN_PROGRESS : 사용자가 진행 시작으로 변경
IN_PROGRESS → DONE        : 사용자가 완료 처리
IN_PROGRESS → NOT_STARTED : 사용자가 진행 취소 (재설정)
DONE        → IN_PROGRESS : 사용자가 완료 취소 (재진행)
```

**비허용 전이:** `NOT_STARTED → DONE`, `DONE → NOT_STARTED` (위 허용 경로 외 모든 전이는 오류 반환)

### 기한 초과 (Overdue) 조건

상태값은 아니지만, 조회 시 별도 필터로 식별한다.

- 조건: `endDate < 오늘 날짜 AND status != DONE`
- 용도: 기한 초과 미완료 할일 목록 필터링
