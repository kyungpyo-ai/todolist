## 2. 제품 개요

### 목적

인증 기반 개인 할일 관리 웹 애플리케이션을 제공한다. 사용자는 카테고리와 날짜 범위를 기반으로 할일을 등록·조회·수정·삭제하며 업무 및 개인 일정을 효율적으로 관리한다.

### 목표

- 1,000명 동시 접속을 처리할 수 있는 안정적인 서비스 운영
- 2일 내 핵심 기능 구현 완료
- 학생 및 직장인(20~50대)이 직관적으로 사용할 수 있는 UX 제공

### 범위

| 포함 (v1) | 포함 (v2) | 제외 |
|-----------|-----------|------|
| 회원가입 / 로그인 / 회원 탈퇴 | 다국어 지원 (i18n) | 소셜 로그인 (Google, Kakao 등) |
| 할일 CRUD | 다크/라이트 모드 (사용자 설정 저장) | 파일 첨부, 알림 기능 |
| 카테고리 CRUD | | 팀/공유 기능 |
| 할일 필터링 및 상태 관리 | | 캘린더 뷰, 통계 대시보드 |
| 반응형 웹 UI | | 네이티브 모바일 앱 |

#### UC-01 회원가입

| 항목 | 내용 |
|------|------|
| 행위자 | 비인증 사용자 |
| 관련 화면 | SCR-02 |
| 도메인 규칙 | BR-09 |

**전제 조건**
- 사용자가 앱에 접근 가능한 상태

**기본 흐름**
1. 사용자가 이름·이메일·비밀번호를 입력하고 가입 버튼을 누른다.
2. 클라이언트가 이메일 형식, 비밀번호 조건(최소 8자, 영문+숫자 조합)을 검증한다.
3. 서버가 이메일 중복 여부를 확인한다.
4. 서버가 계정을 생성하고 `기본` 카테고리를 자동으로 생성한다.
5. 로그인 화면(SCR-01)으로 이동한다.

**예외 흐름**
- 이메일 형식 오류 → 클라이언트에서 즉시 안내 메시지 표시, 제출 차단
- 비밀번호 조건 미충족 → 클라이언트에서 즉시 안내 메시지 표시, 제출 차단
- 이미 가입된 이메일 → 서버 응답 후 "이미 사용 중인 이메일입니다" 오류 표시

#### UC-02 로그인

| 항목 | 내용 |
|------|------|
| 행위자 | 비인증 사용자 |
| 관련 화면 | SCR-01 |
| 도메인 규칙 | BR-01 |

**전제 조건**
- 가입된 계정이 존재한다.

**기본 흐름**
1. 사용자가 이메일·비밀번호를 입력하고 로그인 버튼을 누른다.
2. 서버가 이메일 존재 여부와 비밀번호 일치 여부를 검증한다.
3. 서버가 JWT 토큰을 발급한다.
4. 클라이언트가 토큰을 저장하고 할일 목록 화면(SCR-03)으로 이동한다.

**예외 흐름**
- 이메일 미존재 또는 비밀번호 불일치 → "이메일 또는 비밀번호를 확인해주세요" 오류 표시 (보안상 원인 구분 없음)

#### UC-08 할일 등록

| 항목 | 내용 |
|------|------|
| 행위자 | 인증 사용자 |
| 관련 화면 | SCR-03, SCR-04 |
| 도메인 규칙 | BR-01, BR-03, BR-04 |

**전제 조건**
- 사용자가 로그인 상태이다.

**기본 흐름**
1. 사용자가 할일 목록 화면(SCR-03)에서 등록 버튼을 누른다.
2. 할일 등록 폼(SCR-04)이 열린다.
3. 사용자가 제목(필수), 설명(선택), 시작일, 종료일, 카테고리를 입력한다.
4. 클라이언트가 날짜 유효성(`endDate >= startDate`)을 검증한다.
5. 서버가 할일을 저장한다. 카테고리 미지정 시 `기본` 카테고리를 자동 적용한다.
6. 할일 목록 화면으로 돌아오고 새 항목이 목록에 반영된다.

**예외 흐름**
- 제목 미입력 → 클라이언트에서 제출 차단, 필드 오류 표시
- `endDate < startDate` → "종료일은 시작일 이후여야 합니다" 오류 표시
- 인증 토큰 만료 → 로그인 화면으로 리다이렉트

#### UC-09 할일 목록 조회

| 항목 | 내용 |
|------|------|
| 행위자 | 인증 사용자 |
| 관련 화면 | SCR-03 |
| 도메인 규칙 | BR-01, BR-02 |

**전제 조건**
- 사용자가 로그인 상태이다.

**기본 흐름**
1. 사용자가 할일 목록 화면(SCR-03)에 진입한다.
2. 서버가 해당 사용자의 전체 할일을 반환한다.
3. 화면에 할일 카드 목록이 표시된다.
4. 사용자가 필터를 선택하면 조건에 맞는 목록으로 즉시 갱신된다.

**필터 조건**

| 필터 | 서버 조건 |
|------|-----------|
| 카테고리 | `categoryId = 선택값` |
| 시작 전 | `status = NOT_STARTED` |
| 진행 중 | `status = IN_PROGRESS` |
| 완료 | `status = DONE` |
| 기한 초과 미완료 | `endDate < 오늘 AND status != DONE` |

**예외 흐름**
- 할일 없음 → 빈 상태 안내 메시지 표시
- 인증 토큰 만료 → 로그인 화면으로 리다이렉트

#### UC-10 할일 수정

| 항목 | 내용 |
|------|------|
| 행위자 | 인증 사용자 |
| 관련 화면 | SCR-03, SCR-04 |
| 도메인 규칙 | BR-02, BR-04, BR-05 |

**전제 조건**
- 사용자가 로그인 상태이고 수정 대상 할일이 본인 소유이다.

**기본 흐름**
1. 사용자가 목록에서 할일을 선택해 수정 폼(SCR-04)을 연다.
2. 기존 값이 폼에 미리 채워진다.
3. 사용자가 제목·설명·날짜·카테고리·상태 중 하나 이상을 변경한다.
4. 클라이언트가 날짜 유효성 및 상태 전이 허용 여부를 검증한다.
5. 서버가 변경 사항을 저장하고 갱신된 할일을 반환한다.
6. 목록 화면에 변경 내용이 반영된다.

**허용 상태 전이**

| 현재 상태 | 변경 가능 상태 |
|-----------|--------------|
| NOT_STARTED | IN_PROGRESS |
| IN_PROGRESS | DONE, NOT_STARTED |
| DONE | IN_PROGRESS |

**예외 흐름**
- `endDate < startDate` → 오류 표시, 저장 차단
- 허용되지 않는 상태 전이 → 해당 옵션 비활성화 또는 오류 표시
- 타인 할일 수정 시도 → 서버에서 403 반환

#### UC-12 다크/라이트 모드 [v2]

| 항목 | 내용 |
|------|------|
| 행위자 | 인증 사용자 |
| 관련 화면 | 전체 화면 헤더, SCR-06 |
| 도메인 규칙 | BR-10 |

**전제 조건**
- 사용자가 로그인 상태이다.

**기본 흐름**
1. 사용자가 상단 헤더의 테마 토글 버튼을 누른다.
2. 클라이언트가 즉시 테마를 전환한다 (Zustand 스토어 업데이트).
3. 서버에 `PATCH /users/me` 요청으로 `theme` 값을 저장한다.
4. 이후 로그인 시 서버에서 `theme` 값을 읽어 자동 적용한다.

**상세 요구사항**

| 구분 | 내용 |
|------|------|
| 지원 모드 | `light` (기본), `dark` |
| 설정 저장 위치 | User 테이블 `theme` 필드 |
| 비로그인 기본값 | `light` |
| 전환 시점 | 헤더 토글 버튼 클릭 즉시 적용 및 서버 저장 |

**예외 흐름**
- 서버 저장 실패 시 → 클라이언트 상태는 유지, 다음 로그인 시 이전 값으로 복원될 수 있음을 감수

#### UC-13 언어 변경 [v2]

3. 서버에 `PATCH /users/me` 요청으로 `language` 값을 저장한다.
4. 이후 로그인 시 서버에서 `language` 값을 읽어 자동 적용한다.

**상세 요구사항**

| 구분 | 내용 |
|------|------|

| 전환 시점 | 드롭다운 선택 즉시 적용 및 서버 저장 |

**예외 흐름**

#### UC-14 달력 뷰 조회

| 항목 | 내용 |
|------|------|
| 행위자 | 인증 사용자 |
| 관련 화면 | SCR-07 |
| 도메인 규칙 | BR-01, BR-02 |

**전제 조건**
- 사용자가 로그인 상태이다.

**기본 흐름**
1. 사용자가 IconNav의 달력 아이콘을 눌러 `/calendar`에 진입한다.
2. 현재 월의 할일 목록을 서버에서 조회한다 (`GET /api/todos?month=YYYY-MM`).
3. 월별 달력에 `start_date` 기준으로 각 날짜 셀에 할일이 표시된다.
4. 이전/다음 월 버튼 클릭 시 해당 월 데이터를 재조회한다.
5. 달력의 할일 항목 클릭 시 상세 모달이 열리고 제목·상태·날짜·카테고리·설명을 확인할 수 있다.

**상세 요구사항**

| 구분 | 내용 |
|------|------|
| 라이브러리 | react-big-calendar (월별 뷰 고정) |
| 날짜 기준 | `start_date` 기준으로 해당 날짜 셀에 표시 |
| 상태별 색상 | NOT_STARTED: 회색, IN_PROGRESS: 파란색, DONE: 초록색 |
| API 파라미터 | `month=YYYY-MM` (`YYYY-MM` 형식 외 입력 시 400 반환) |

**예외 흐름**
- 해당 월 할일 없음 → 빈 달력 표시

## 8. 제약사항 및 가정

### 기술 제약

- ORM으로 Prisma 사용 금지. pg 라이브러리 직접 사용
- 모바일은 반응형 웹으로만 지원 (네이티브 앱 없음)
- 접근성(a11y) 고려 없음

### 일정 제약

- 핵심 기능(Must Have) 2일 내 완성
- Should Have 기능은 일정 내 여유가 있을 경우 포함

### 예산 제약

- 1인 개발 수준의 인프라 비용
- 고가용성 구성 및 CDN 등 추가 인프라 미적용

### 가정

- 초기 사용자 규모는 1,000명 동시 접속 기준으로 설계
- 인증 방식은 JWT를 사용하며 별도 세션 저장소 없음
- 이메일 인증(이메일 발송) 기능은 포함하지 않음
