## 3. 페르소나 정의

### P1. 대학생 — 김지수 (22세)

- **배경:** 공과대학 3학년. 수업, 과제 제출, 팀 프로젝트, 시험 준비가 동시에 몰리는 학기 중 시간 관리에 어려움을 겪고 있다.
- **목표:** 마감일 기준으로 할일을 분류하고, 기한 내 처리 여부를 한눈에 확인하고 싶다.
- **디바이스:** 주로 노트북, 이동 중에는 스마트폰 브라우저 사용.
- **불만:** 메모장이나 카카오톡 자기 자신에게 보내기로 관리하다 보니 무엇이 완료됐는지 기억이 나지 않는다.

### P2. 직장인 — 박성훈 (35세)

- **배경:** IT 회사 중간 관리자. 업무 태스크와 개인 용무(병원 예약, 가족 행사 등)를 분리해서 관리하고 싶다.
- **목표:** 카테고리로 업무/개인을 나누고, 오늘 처리해야 할 항목과 기한 초과 항목을 빠르게 식별한다.
- **디바이스:** 사무실 PC, 퇴근 후 태블릿.
- **불만:** 회사 협업 툴은 업무 전용이라 개인 일정을 섞기 어렵다. 간단하고 빠른 개인 툴이 필요하다.

### P3. 직장인 — 이수연 (42세)

- **배경:** 마케팅 팀장. 야간 작업이 잦아 어두운 화면을 선호하며, 해외 파트너와의 소통 때문에 영어 UI에도 익숙하다.
- **목표:** 다크 모드로 눈의 피로를 줄이고, 언어를 영어로 바꿔 업무 흐름을 통일하고 싶다.
- **디바이스:** MacBook Pro, 사내 듀얼 모니터.
- **불만:** 매번 로그인할 때마다 테마가 초기화되는 앱들이 불편하다.

### US-01. 신규 사용자 온보딩 — 회원가입 후 첫 할일 등록

**페르소나:** P1 김지수 | **관련 UC:** UC-01, UC-02, UC-08

**상황:**
중간고사 2주 전, 지수는 과목별 시험 공부 계획을 세우려고 한다. 친구 추천으로 TodoList 앱을 처음 접속했다.

**행동 흐름:**

1. 앱에 접속하면 로그인 화면(SCR-01)이 보인다. 지수는 아직 계정이 없어 "회원가입" 링크를 클릭한다.
2. 회원가입 화면(SCR-02)에서 이름 `김지수`, 이메일 `jisu@university.ac.kr`, 비밀번호 `study2026`을 입력한다.
3. 가입 버튼을 누르자 서버가 계정을 생성하고 `기본` 카테고리가 자동으로 만들어진다. 화면은 로그인 화면으로 이동한다.
4. 방금 만든 이메일과 비밀번호로 로그인하면 할일 목록 화면(SCR-03)으로 진입한다. 목록은 비어 있다.
5. 등록 버튼을 눌러 할일 등록 폼(SCR-04)을 열고, 제목 `알고리즘 기말 대비`, 시작일 `2026-05-27`, 종료일 `2026-06-10`, 카테고리 `기본`을 입력한 뒤 저장한다.
6. 목록 화면으로 돌아오면 방금 등록한 할일 카드가 표시된다.

**결과:**
지수는 처음 앱에 접속한 지 3분 만에 첫 할일을 등록하고, 앞으로 추가할 과목별 계획의 기반을 마련했다는 안도감을 느낀다.

---

### US-02. 일상적인 할일 관리 — 조회, 필터링, 상태 변경

**페르소나:** P2 박성훈 | **관련 UC:** UC-02, UC-09, UC-10

**상황:**
월요일 오전, 성훈은 출근하자마자 이번 주 처리해야 할 일과 이미 놓친 마감을 확인하려 한다.

**행동 흐름:**

1. 로그인 후 할일 목록 화면(SCR-03)에 진입하면 등록된 모든 할일이 카드 형태로 표시된다.
2. `기한 초과 미완료` 필터를 선택한다. 오늘 날짜 기준으로 종료일이 지났으나 완료되지 않은 항목 2건이 별도로 보인다.
3. 그 중 하나는 이미 처리했음을 인지하고 해당 카드를 클릭해 수정 폼(SCR-04)을 연다. 상태를 `IN_PROGRESS`에서 `DONE`으로 변경하고 저장한다.
4. 나머지 1건은 아직 진행 중이므로 종료일을 이번 주 금요일로 수정하고 저장한다.
5. 이번에는 `진행 중` 필터를 선택해 현재 처리 중인 할일 목록을 확인하고 우선순위를 머릿속으로 정리한다.

**결과:**
성훈은 5분 만에 놓친 마감을 처리하고, 이번 주 업무 우선순위를 명확히 파악했다. 주간 스탠드업 미팅 전에 현황을 빠르게 정리할 수 있었다.

---

### US-03. 카테고리를 활용한 할일 분류

**페르소나:** P2 박성훈 | **관련 UC:** UC-05, UC-08, UC-10

**상황:**
앱을 쓴 지 일주일이 지났다. 업무 할일과 개인 할일이 뒤섞여 목록이 복잡해졌다. 성훈은 카테고리로 분리해서 관리하기로 결심한다.

**행동 흐름:**

1. 카테고리 관리 화면(SCR-05)으로 이동해 `업무`와 `개인` 카테고리를 각각 생성한다.
2. 기존에 `기본` 카테고리에 몰려 있던 할일들 중 업무 관련 항목을 하나씩 열어 카테고리를 `업무`로 변경·저장한다.
3. 병원 예약, 자동차 보험 갱신 같은 개인 항목은 `개인` 카테고리로 이동한다.
4. 이후부터는 새 할일을 등록할 때마다 카테고리를 명시적으로 지정한다.
5. 목록 화면에서 `업무` 카테고리 필터만 선택하면 업무 할일만 깔끔하게 표시된다.

**결과:**
성훈은 카테고리 분류 이후 업무 집중 시간에는 `업무` 필터, 주말에는 `개인` 필터로 목록을 전환하며 맥락 전환의 부담을 줄일 수 있었다.

---

### US-04. 기한 초과 할일 확인 및 처리

**페르소나:** P1 김지수 | **관련 UC:** UC-09, UC-10, UC-11

**상황:**
시험 준비에 집중하다 2주 동안 앱을 거의 안 봤다. 로그인하고 보니 기한이 지난 항목이 쌓여 있어 불안하다.

**행동 흐름:**

1. 로그인 후 목록 화면에서 `기한 초과 미완료` 필터를 선택한다. 기한이 지난 미완료 항목 5건이 표시된다.
2. 각 항목을 검토한다.
   - 이미 완료한 과제 2건 → 상태를 `DONE`으로 변경한다.
   - 여전히 해야 하는 리포트 제출 1건 → 종료일을 다음 주로 연장하고 상태는 `IN_PROGRESS`로 변경한다.
   - 더 이상 필요 없는 항목 2건 → 삭제 확인 다이얼로그에서 확인을 눌러 삭제한다.
3. 필터를 해제하면 정리된 전체 목록이 깔끔하게 보인다.

**결과:**
지수는 밀린 할일 현황을 빠르게 파악하고 정리했다. 기한 초과 필터 덕분에 전체 목록을 하나하나 훑지 않아도 문제 항목만 집중해서 처리할 수 있었다.

### US-05. 내 정보 수정

**페르소나:** P2 박성훈 | **관련 UC:** UC-03

**상황:**
보안 정책상 3개월마다 비밀번호를 바꾸는 습관이 있다. 또한 처음 가입할 때 이름을 오타 낸 것도 함께 수정하려 한다.

**행동 흐름:**

1. 헤더 또는 메뉴에서 내 정보 화면(SCR-06)으로 이동한다.
2. 이름 필드에 올바른 이름 `박성훈`을 다시 입력한다.
3. 비밀번호 변경 섹션에서 현재 비밀번호, 새 비밀번호 `Secure2026!`, 새 비밀번호 확인을 차례로 입력한다.
4. 저장 버튼을 누르면 서버가 변경 사항을 저장하고 성공 메시지를 반환한다.

**결과:**
성훈은 이름 오타와 비밀번호 갱신을 한 번의 화면 방문으로 처리했다. 변경 후 목록 화면에서 이름이 즉시 반영된 것을 확인한다.

### US-06. 다크 모드 전환 및 재로그인 후 유지 확인

**페르소나:** P3 이수연 | **관련 UC:** UC-12

**상황:**
야근 중 밝은 화면이 눈에 부담스럽다. 이수연은 다크 모드로 전환하고 내일 다시 로그인해도 설정이 유지되길 원한다.

**행동 흐름:**

1. 할일 목록 화면 상단 헤더에서 테마 토글 버튼을 클릭한다.
2. 화면 전체가 즉시 다크 테마로 전환된다. 배경은 어두워지고 텍스트는 밝게 바뀐다.
3. 클라이언트는 동시에 서버로 `PATCH /users/me` 요청을 보내 `theme: dark`를 저장한다.
4. 다음 날 아침 로그인하면 서버에서 저장된 `theme: dark` 값을 읽어 다크 모드가 자동으로 적용된다. 별도 설정 없이 어제의 환경 그대로다.
5. 낮에 다시 라이트 모드로 전환하고 싶으면 토글을 한 번 더 클릭하면 된다.

**결과:**
이수연은 매번 로그인할 때마다 테마를 다시 설정해야 하는 불편 없이, 자신이 선호하는 환경을 유지하며 작업할 수 있다.

### US-07. 언어 변경 — 한국어에서 영어로 전환

**페르소나:** P3 이수연 | **관련 UC:** UC-13

**상황:**
해외 파트너에게 할일 목록 화면을 공유해야 하는 상황이 생겼다. UI를 영어로 바꿔서 파트너가 내용을 이해할 수 있도록 하고 싶다.

**행동 흐름:**

1. 내 정보 화면(SCR-06)으로 이동한다.
2. 언어 설정 드롭다운에서 `English`를 선택한다.
3. i18next가 즉시 전체 UI 언어를 영어로 전환한다. 버튼 레이블, 오류 메시지, 플레이스홀더 모두 영어로 바뀐다.
4. 서버에 `PATCH /users/me` 요청으로 `language: en`이 저장된다.
5. 파트너와의 미팅이 끝난 후 다시 드롭다운에서 `한국어`를 선택해 원래 언어로 복귀한다.

**결과:**
이수연은 설정 화면 한 곳에서 언어를 즉시 전환할 수 있었다. 앱을 재시작하거나 새로고침 없이도 전체 UI가 바뀌어 해외 파트너와의 소통 준비를 빠르게 마쳤다.

### UE-01. 잘못된 날짜 입력 — 종료일이 시작일보다 앞선 경우

**페르소나:** P1 김지수 | **관련 UC:** UC-08, UC-10

**상황:**
급하게 할일을 등록하다가 실수로 시작일을 `2026-06-10`, 종료일을 `2026-06-01`로 잘못 입력했다.

**행동 흐름:**

1. 할일 등록 폼(SCR-04)에서 제목, 시작일 `2026-06-10`, 종료일 `2026-06-01`을 입력하고 저장 버튼을 누른다.
2. 클라이언트가 `endDate < startDate` 조건을 감지하고 "종료일은 시작일 이후여야 합니다"라는 오류 메시지를 폼 내에 즉시 표시한다.
3. 서버 요청은 차단된다. 데이터는 저장되지 않는다.
4. 지수는 오류 메시지를 보고 종료일을 `2026-06-20`으로 수정한 뒤 다시 저장한다.
5. 정상 저장되어 목록 화면으로 돌아온다.

**결과:**
잘못된 날짜 조합이 서버까지 전달되지 않아 데이터 정합성이 유지된다. 지수는 명확한 오류 안내 덕분에 어디를 수정해야 할지 즉시 파악했다.

### UE-02. 기본 카테고리 삭제 시도

**페르소나:** P2 박성훈 | **관련 UC:** UC-07

**상황:**
카테고리를 정리하다가 `기본` 카테고리도 지우면 더 깔끔할 것 같아 삭제 버튼을 찾는다.

**행동 흐름:**

1. 카테고리 관리 화면(SCR-05)에서 `기본` 카테고리 항목을 확인한다.
2. `기본` 카테고리에는 삭제 버튼 자체가 비활성화(disabled) 상태로 표시된다.
3. 성훈은 해당 버튼을 클릭할 수 없음을 인식한다. 실수로 API를 직접 호출해도 서버는 403을 반환한다.

**결과:**
시스템의 안전망이 작동해 `기본` 카테고리가 삭제되는 상황 자체가 발생하지 않는다. 성훈은 삭제가 불가능한 항목임을 UI에서 직관적으로 파악했다.

### UE-03. 중복 이메일로 회원가입 시도

**페르소나:** P1 김지수 | **관련 UC:** UC-01

**상황:**
지수가 이미 가입한 이메일 주소로 친구가 같은 앱에 가입하려 한다. 또는 지수 본인이 가입 여부를 잊고 다시 가입을 시도한다.

**행동 흐름:**

1. 회원가입 화면(SCR-02)에서 이미 등록된 이메일 `jisu@university.ac.kr`과 이름, 비밀번호를 입력하고 가입 버튼을 누른다.
2. 클라이언트 측 형식 검증은 통과한다.
3. 서버가 이메일 중복 여부를 확인하고 "이미 사용 중인 이메일입니다" 오류 응답을 반환한다.
4. 화면에 오류 메시지가 표시되며 계정은 생성되지 않는다.
5. 사용자는 로그인 화면으로 이동하거나 다른 이메일로 재시도할 수 있다.

**결과:**
동일 이메일로 중복 계정이 생성되는 것을 방지한다. 사용자는 이미 가입된 계정이 있음을 인지하고 로그인으로 전환할 수 있다.
